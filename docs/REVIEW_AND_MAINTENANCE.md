# 程序审查与维护说明

本文记录当前程序的结构、关键数据流、已识别风险和后续维护建议。它的目标不是替代代码，而是让后续改动先知道哪些地方容易互相影响。

## 当前结构

- `src/main.ts` 是前端主入口，同时承载桌宠渲染、桌面窗口交互、Android 全屏模式、右键设置菜单、蒙版编辑器、互动控件、LLM 调用、语音与历史记录等逻辑。
- `src-tauri/src/lib.rs` 是 Tauri 后端入口，负责窗口移动、窗口缩放、右键菜单独立窗口、蒙版编辑器独立窗口、配置文件读写、皮肤文件读写、全局快捷键和移动端兼容命令。
- `src-tauri/tauri.conf.json` 定义桌面主窗口、权限和 WebView 安全策略。
- `src-tauri/tauri.android.conf.json` 定义 Android 包名、窗口标题和移动端构建配置。
- `src-tauri/gen/android/app/src/main/java/com/live2d/desktoppet/MainActivity.kt` 对 Android WebView 做原生侧收口，当前主要禁用系统缩放和长按菜单。

## 运行模式

程序目前不是单一界面，而是同一份前端代码根据 `view` 参数和平台分成多种模式。

- 桌面主桌宠：默认入口，透明置顶窗口，尺寸跟随桌宠缩放。
- 桌面设置菜单：`?view=settings-menu`，由 Tauri 创建独立透明窗口，因此不受桌宠窗口边界裁剪。
- 桌面蒙版编辑器：`?view=mask-editor`，由 Tauri 创建独立普通窗口，用于编辑身体部位蒙版。
- Android 桌宠：`isMobileRuntime()` 为真时进入全屏移动端布局，设置、工具、对话栏固定在屏幕内。

维护时要注意：很多函数被多种模式复用。改桌面窗口逻辑时，需要确认 Android stub 仍能安全返回；改 Android 布局时，也要确认桌面透明窗口的穿透策略没有被影响。

## 关键数据流

### 互动命中

1. 用户点击或拖动桌宠。
2. 前端用 `getPetImagePointFromClient()` 把屏幕坐标反算成当前立绘原始图片坐标。
3. 如果当前皮肤存在用户保存的蒙版，优先用蒙版做命中检测。
4. 如果没有用户蒙版，退回到自动推测规则。
5. 命中结果进入互动控件、提示词构造、历史记录和 LLM 请求。

这条链路对坐标、缩放、窗口尺寸、图片自然尺寸都敏感。近期问题集中在这里，后续修改应优先补测试。

### 蒙版层级

蒙版层级有两套语义：

- 用户在编辑器里显式设置过层级时，使用用户层级。
- 没有显式层级时，默认小部位优先于大部位，避免头发、身体等大区域遮住五官、饰品等小区域。

维护时不要只按数组顺序或绘制顺序判断命中优先级，否则会再次出现大蒙版挡住小部位的问题。

### 设置菜单

桌面右键菜单是独立窗口，不是主桌宠窗口里的浮层。它的定位由 Tauri 后端根据点击锚点和虚拟屏幕边界计算：

- 右下空间足够时，从点击点向右下展开。
- 贴近右侧或底部时，向左或向上翻转。
- 窗口复用时先隐藏、重定位、再显示，避免用户看到旧位置闪动。

### Android

Android 第一阶段是全屏应用，不是系统悬浮窗。桌宠交互、蒙版入口、工具栏和对话栏都应被限制在屏幕内，不能跟随桌宠缩放漂出屏幕。

原生 `MainActivity` 禁用了 WebView 缩放和长按菜单。前端还需要禁用文本选择、触控高亮和浏览器手势，避免点击出现蓝色选中或长按弹出系统菜单。

## 持久化数据

前端主要使用 `localStorage` 保存用户可编辑状态，例如：

- 互动控件和独立提示词。
- 蒙版部位、层级、名称和独立提示词。
- 当前皮肤、缩放、UI 展开状态等界面状态。

Tauri 后端主要保存更偏系统或文件的数据，例如：

- LLM 配置和 API Key。
- 互动历史。
- 自定义皮肤目录和图片。

涉及隐私和安全的改动必须确认数据保存位置、清理入口和错误提示。LLM 配置、用户输入、模型回复都可能包含敏感内容。

## 审查结论

### 1. WebView 安全面需要收紧

`src-tauri/tauri.conf.json` 当前启用了 `withGlobalTauri`，同时 `csp` 为 `null`。这对本地开发方便，但扩大了 XSS 后果：如果未来某处把用户文本、模型回复或第三方内容作为 HTML 注入，攻击代码会更容易触达 Tauri 命令。

建议：

- 补明确 CSP，至少限制脚本、样式、图片和连接来源。
- 长期改为通过显式 import 使用 Tauri API，减少 `window.__TAURI__` 暴露面。
- 所有模型输出和用户输入继续使用 `textContent` 或框架安全渲染，不使用 `innerHTML`。

### 2. 默认互动内容有发行风险

默认身体部位和互动控件包含成人、暴力或强敏感词。这些内容目前不只是文案，会参与 UI、历史记录、命中语义和 LLM 提示词。

建议：

- 如果目标包含 Android 分发或公开发行，提供普通模式默认词表。
- 将敏感互动做成用户可导入配置，而不是默认内置。
- LLM 提示词构造前增加内容模式判断，避免默认把敏感部位或敏感动作送入模型。

### 3. `src/main.ts` 过大，回归风险高

当前主入口已经同时处理 UI、几何、持久化、Tauri 调用、LLM、语音、移动端适配和蒙版编辑。功能可以运行，但维护成本偏高，尤其是最近反复修改的窗口尺寸、坐标映射、蒙版层级和移动端固定工具栏。

建议拆分：

- `geometry.ts`：图片坐标、缩放、旋转、命中检测。
- `masks.ts`：蒙版模型、层级、序列化、默认规则迁移。
- `interactions.ts`：互动控件、提示词合成、历史记录输入结构。
- `runtime.ts`：桌面和 Android 的平台差异。
- `windows.ts`：Tauri 窗口调用封装。

拆分前不要大规模重写 UI。先把纯函数抽出并补测试，更容易控制风险。

### 4. 自动化测试不足

当前缺少针对以下行为的自动化保护：

- 缩放 30% 到 300% 时，点击坐标是否仍映射到正确图片位置。
- 蒙版重叠时，小部位默认优先、用户显式层级优先。
- 桌面右键菜单在屏幕边缘是否正确翻转。
- Android 工具栏、设置入口、对话栏是否固定在屏幕内。
- WebView 是否不会出现蓝色选中和长按系统菜单。

建议优先添加轻量测试：

- 对几何和蒙版命中做单元测试。
- 对桌面菜单定位做 Rust 单元测试或抽函数测试。
- 对 Android/桌面布局做 Playwright 截图烟测。

### 5. Android 构建依赖需要文档化

Android 构建依赖 Android SDK、NDK、JDK 和 Windows 符号链接能力。Windows 上如果没有 Developer Mode 或管理员权限，Tauri Android 构建可能因为创建符号链接失败。

建议：

- 在本仓库文档中固定推荐的 SDK/NDK/JDK 版本。
- 记录 Windows Developer Mode 要求。
- CI 或发布脚本中尽量使用可重复的环境变量设置。

## 推荐维护流程

1. 修改坐标、窗口尺寸、缩放或蒙版逻辑前，先确认影响桌面主窗口、设置菜单窗口、蒙版编辑器和 Android 四种模式。
2. 新增互动字段时，同步检查默认值、localStorage 迁移、编辑器表单、LLM 提示词和历史记录展示。
3. 新增蒙版字段时，同步检查默认规则、用户保存数据、层级排序、命中检测和编辑器渲染。
4. 修改 Android 触控时，同时验证点击、拖动、长按、双指缩放、侧边工具栏和底部对话栏。
5. 发布前至少运行：

```powershell
npm run build
cd src-tauri
cargo check
```

Android 构建检查建议在配置好 SDK/NDK 后运行：

```powershell
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
$env:NDK_HOME="$env:LOCALAPPDATA\Android\Sdk\ndk\29.0.14206865"
$env:PATH="$env:NDK_HOME\toolchains\llvm\prebuilt\windows-x86_64\bin;$env:PATH"
cargo check --target aarch64-linux-android --features "tauri/custom-protocol"
```

## 优先级建议

近期最值得做的是把几何和蒙版命中逻辑从 `src/main.ts` 抽出来并加测试。这部分直接决定桌宠是否能点中、蒙版是否偏移、缩放后是否还能交互，也是最容易被 UI 改动间接破坏的区域。
